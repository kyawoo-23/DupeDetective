A reviewer still has to say what the match means.

Coding assistants make it easy to add another button, card, or field. Three different situations can look the same in a pull request.

Accidental copy The same component, written again.
Intentional variant A real difference that should stay.
Same shape, different job Shared structure, unrelated meaning.

Built for the person who has to decide.

A frontend tech lead or design-system maintainer inspects the evidence, records one decision per group, and hands the cleanup to a coding agent.

The reviewer does

  • Scan a public GitHub repo or a ZIP.
  • Compare source and a sandboxed preview.
  • Choose Merge or Keep separate, with a note.

The product does

  • Find candidates with fixed AST rules.
  • Explain which signals matched.
  • Write a backlog and a repair instruction.

Four steps from scan to instruction.

01 Scan

Public GitHub URL or ZIP. The commit SHA, or a ZIP hash, stays with the scan.

02 Group

Pairs join while the average stays at 28 or above. 40 or higher reads as Strong.

03 Decide

Keep one component, merge the rest, or keep them separate. Scores only order the queue.

04 Hand off

Copy the backlog and the agent instruction. The repo is never written.

The evidence is a weighted checklist.

A token that shows up everywhere counts for less than a rare one. A group score is the average of every pair inside it.

Signal Weight
JSX element tree 35
Prop name overlap 25
Event handler overlap 15
Nesting depth 10
Shared class names 10
Component name 5

Any coding agent can run the repair.

Detection stays deterministic

  • AST structure, fixed weights, visible evidence.
  • A match is a candidate for review.
  • A new scan starts with no prior decisions.

The agent enters at the end

  • Copy one instruction, or the whole set.
  • Paste it into Bob, Cursor, or any other coding agent.
